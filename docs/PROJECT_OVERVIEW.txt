1. Project Summary
This project is a self-hosted AI educational tutor chatbot for AILernova.
It uses a Retrieval-Augmented Generation (RAG) architecture to answer questions only from lesson PDF content.
The system is designed to avoid external AI APIs and runs fully on local or self-hosted components.

Main purpose:
- ingest lesson PDFs
- convert them into searchable vector embeddings
- retrieve relevant lesson text for a user question
- generate an answer grounded in those lesson chunks
- expose the chatbot through a React floating widget

2. Core Architecture
High-level architecture:

User -> React Widget -> FastAPI Backend -> Retriever -> ChromaDB
                                         -> Ollama LLM
                                         -> Lessons PDF Content

Detailed flow:
1. User asks a question in the widget.
2. Widget sends the question and conversation history to the backend.
3. Backend embeds the question.
4. Backend searches ChromaDB for the most relevant lesson chunks.
5. Backend builds a strict prompt using only those retrieved chunks.
6. The backend prefers an extractive lesson-grounded answer path and can fall back to LLM generation.
7. Ollama generates an answer when needed.
8. Backend filters the answer so unsupported statements are removed.
9. Backend returns the final validated text to the widget.
10. Widget renders the reply.

6.2 API Endpoints
File:

Endpoints:
- GET / -> basic API running message
- GET /api/v1/health -> checks backend, Ollama, ChromaDB
- POST /api/v1/ask -> answer user question from lessons
- POST /api/v1/ingest -> upload and ingest PDF

6.3 Ask Flow
POST /api/v1/ask
Request format:
{
  "question": "What are loops?",
  "messages": [
    {"role": "user", "content": "previous question"},
    {"role": "assistant", "content": "previous answer"}
  ]
}

Flow:
1. validate question is not empty
2. retrieve relevant chunks from ChromaDB
3. if no chunks found, return lesson-content-not-available response
4. generate strict answer from lesson chunks
5. return plain text response

7. RAG Pipeline
7.1 Ingestion
File:
- backend\app\ingest\processor.py

Steps:
1. open PDF with PyMuPDF
2. extract page text
3. split text into chunks
4. embed chunks using SentenceTransformers
5. store embeddings and metadata in ChromaDB

7.2 Retrieval
File:
- backend\app\rag\retriever.py

Steps:
1. embed user query
2. query ChromaDB collection
3. return top relevant chunks with metadata

7.3 Generation and Strictness
File:
- backend\app\rag\generator.py

Current behavior:
- builds prompt from retrieved lesson chunks
- respects formatting requests like point wise, bullet points, short
- blocks unsupported generalizations
- has strict filtering for claims not supported by lesson chunks
- prefers an extractive answer path for strict lesson-grounded responses
- falls back to the refusal text when lesson support is insufficient

Strictness rules currently include:
- no invented definitions
- no invented benefits or importance claims
- no broad generalization beyond lesson wording
- unsupported points should be omitted

15. Troubleshooting
Problem: localhost:8080 shows folder listing
Cause:
- dist\index.html missing
Fix:
- rebuild widget so demo page is copied into dist

Problem: backend not responding
Check:
- backend process running
- health URL
- wait for model startup time

Problem: health shows Ollama unreachable
Check:
- Ollama running on 11434
- model pulled: llama3.2

Problem: answers too generic
Check:
- retrieved lesson content exists
- seed data is current
- backend strict answer logic is active

Problem: lesson changes not reflected
Fix:
- regenerate PDF if needed
- run python seed.py again
- restart backend

Problem: formatting not updating in browser
Fix:
- rebuild widget
- hard refresh browser

16. Known Constraints
- backend startup is not instant
- local model generation may be slower than cloud APIs
- strict context mode may make answers less natural, but more accurate to lessons
- answer quality depends on lesson content coverage
- if lesson text does not contain a fact, the system should not invent it
- strict extractive mode may still need cleanup improvements for sentence selection and deduplication
