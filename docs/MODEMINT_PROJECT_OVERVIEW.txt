ModeMint - Project Overview
Project root: D:\Project\

1. Project Summary
ModeMint is an AI fashion outfit recommender built as a Flask web application.
It helps users:
- generate outfit recommendations from a product catalog
- manage a personal wardrobe
- upload wardrobe images for clothing detection
- save favorite outfits
- chat with an AI stylist

The app is a monolithic web application:
- Flask serves the API
- Flask also serves the frontend HTML, CSS, and JS
- data is stored in JSON files, not in a database

2. Core Architecture
High-level architecture:

User Browser
  -> Flask app
     -> static frontend pages
     -> API routes
        -> recommendation engine
        -> wardrobe storage
        -> clothing detection
        -> AI chat service
        -> JSON data files

Main runtime components:
- Frontend: static HTML/CSS/JS served by Flask
- Backend: Flask application
- AI chat provider: Groq via OpenAI SDK compatibility
- Local fallback chat logic if external AI fails
- Wardrobe detection: YOLO via ultralytics with filename fallback
- Persistence: JSON files and uploaded images

9. Recommendation Engine Flow
Route:
- POST /recommend

Implementation:
- backend\routes\recommend.py
- backend\services\recommendations.py

Flow:
1. Frontend sends occasion, style, and budget
2. Backend normalizes inputs
3. Backend loads products from `backend/data/products.json`
4. Backend filters products by:
   - budget
   - occasion
   - style
5. Products are grouped into required categories:
   - top
   - bottom
   - shoes
   - accessory
6. All valid category combinations are generated
7. Each outfit is scored using:
   - occasion match
   - style match
   - trend score
   - trend boost from trend data
   - local designer bonus
   - budget bonus
8. Outfits are sorted and top results are returned

Returned response includes:
- query info
- outfits list
- summary metadata

10. Wardrobe Flow
Route group:
- GET /wardrobe
- POST /wardrobe
- POST /wardrobe/upload
- DELETE /wardrobe/<id>
- POST /wardrobe/generate

Implementation:
- backend\routes\wardrobe.py
- backend\services\detection.py
- backend\services\recommendations.py

Wardrobe storage:
- backend/data/wardrobe.json

10.1 Manual wardrobe item creation
1. Frontend sends item fields to POST /wardrobe
2. Backend validates required fields
3. Backend appends item to wardrobe JSON
4. Saved item is returned

10.2 Image upload and analysis
1. Frontend uploads image to POST /wardrobe/upload
2. Backend saves image to `backend/uploads/`
3. Backend runs clothing detection
4. Detection returns inferred wardrobe items and labels
5. Frontend can use detected values to help create wardrobe entries

10.3 Generate outfits from wardrobe
1. Frontend sends occasion and style to POST /wardrobe/generate
2. Backend loads wardrobe items
3. Backend groups items by required categories:
   - top
   - bottom
   - shoes
4. Optional accessories are added to combinations
5. Outfits are scored and returned

11. Clothing Detection Flow
Implementation:
- backend\services\detection.py

How it works:
1. Determine dominant color using a lightweight OpenCV heuristic
2. Try to load YOLO model from:
   - backend/static/yolov8n.pt
3. If model is available, run detection on uploaded image
4. Keep only conservative fashion-related labels
5. Map detected labels to wardrobe item categories and metadata
6. If model is unavailable or detection fails, guess item from filename
7. If filename also gives no good clue, return a generic fallback item

Important limitation:
- The YOLO model is general-purpose, not fashion-specialized
- Detection quality is best-effort only

12. AI Chat Flow
Route:
- POST /chat

Implementation:
- backend\routes\chat.py
- backend\services\openai_service.py

Primary behavior:
1. Frontend sends a free-text styling prompt
2. Backend tries to create a Groq-compatible OpenAI client
3. Backend builds app context from:
   - catalog products
   - wardrobe items
   - favorites
   - trends
4. Backend sends the request to the configured Groq model
5. Backend returns the generated styling response

Fallback behavior:
If Groq API fails or `GROQ_API_KEY` is missing:
1. Backend uses `build_local_chat_response()`
2. Local logic infers:
   - occasion
   - style
   - budget
   - whether wardrobe/favorites/local/trends should be prioritized
3. Backend builds a rule-based recommendation response

Important note:
- Chat is not purely local by default
- It prefers Groq when credentials are configured

15. Environment Variables
From `.env.example`:
- GROQ_API_KEY=your-groq-api-key-here
- GROQ_MODEL=openai/gpt-oss-20b

What they do:
- GROQ_API_KEY: enables external AI chat through Groq
- GROQ_MODEL: selects the model used by the Groq/OpenAI-compatible client
- FLASK_ENV: runtime environment mode

20. Troubleshooting
Problem: app does not start
Check:
- dependencies installed
- virtual environment activated
- correct Python version

Problem: chat returns fallback instead of AI model
Check:
- GROQ_API_KEY is present in `.env`
- outbound network access is available
- Groq model name is valid

Problem: wardrobe upload fails
Check:
- image extension is jpg, jpeg, png, or webp
- uploads directory exists and is writable

Problem: clothing detection is weak or generic
Check:
- whether `backend/static/yolov8n.pt` exists
- remember detection is best-effort and not fashion-specialized

Problem: recommendations are empty
Check:
- `products.json` contains enough items in all required categories
- category coverage exists for selected style and occasion
- budget is high enough

Problem: favorites or wardrobe are not saved
Check:
- backend/data is writable
- JSON files are not corrupted

21. Known Constraints
- No database; persistence is file-based
- Chat quality depends on Groq API availability or local fallback quality
- YOLO detection is approximate and not fashion-specific
- Frontend is static/vanilla JS, not component-based React/Vue
- Recommendation quality depends on product and trend JSON quality
